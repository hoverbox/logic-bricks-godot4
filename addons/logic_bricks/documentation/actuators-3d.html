3D Setup and Actions

Use this section when the selected object is a Node3D-based gameplay object. The categories below follow the action submenus shown in the Logic Bricks right-click menu.

1

Select a 3D node

Select a Node3D, CharacterBody3D, RigidBody3D, Camera3D, light, or another supported 3D node in the Scene dock.

2

Open Logic Bricks

Open the Logic Bricks editor. The addon detects the selected node as a 3D context and filters the available bricks accordingly.

3

Build the chain

Add a Trigger , an optional Gate , and an Action. Target-node fields can point to other nodes when an action should affect something else.

4

Choose by submenu

Right-click the graph, open Actions, and choose the same submenu shown in the category links below.

How this relates to the menu

Actions shared by 3D and 2D, such as variables, signals, states and transforms, are listed under their submenus on this page as well as on the 2D page.

3rd Person Camera

3D

Orbits a Camera3D around the character via a pivot Node3D. The pivot and camera can live anywhere in the edited scene. With Avoid Walls on, the camera moves in front of walls that would block the view, looks past pillars and posts, and eases back out when the view is clear.

Recommended setup 
CharacterBody3D
├── CameraPivot (Node3D)
└── Camera3D

Place CameraPivot around head/shoulder height. Place Camera3D behind and above the pivot, then choose both nodes in the brick's scene dropdowns. The brick records that starting camera offset and uses it as the orbit distance (or set Camera Distance).

Run this action continuously, for example Always → AND → 3rd Person Camera. Mouse/gamepad orbit and pitch clamping are handled by the brick. Turn on Avoid Walls in the Wall Avoidance group so walls never block the view.

Turning the character

The camera does not turn the character. (Rotate Character, Align Mode, Turn Speed and Move Actions were removed in version 3.7.2.) For third-person movement, turn on Camera Relative in Position so the input moves the character relative to the camera, and add Look At Input with Camera Relative on so the character faces the direction it moves.

Avoid Walls

When Avoid Walls is on, the brick adds a SpringArm3D under the pivot when the game starts. The character's own colliders are ignored.

  • Walls: when something on the Collision Mask layers blocks the view, the camera moves in front of it at once, so it never ends up inside a wall. When the view is clear again, it eases back out over Return Smoothing seconds.
  • Pillars, posts and trees: anything narrower than Narrow Obstacle Width that passes between the camera and the player does not pull the camera in. The view is only blocked for a moment. The camera tests whether it can see around the obstacle to the left and right, so this works for any collider, including one mesh collider for a whole room with its pillars. The camera still never comes to rest inside a pillar: if a pillar sits where the camera would be, it stops just in front of it. Set the width to 0 to treat every obstacle as a wall.
  • Thin things in a row (fences, railings): Probe Radius sweeps a small sphere instead of a thin line, which stops the camera popping in and out between posts.
  • Put small props and foliage on a physics layer that is not in Collision Mask when the camera should ignore them completely. Collision Mask accepts layer numbers (1, 3) or layer names from Project Settings → Layer Names → 3D Physics.

Smooth Physics Motion

The character moves on physics ticks, which can look like stutter on high-refresh screens. With Smooth Physics Motion on (default), pressing Apply Code turns on Project Settings → Physics → Common → Physics Interpolation, and the camera follows the smoothed position. Restart the running game after Apply Code changes the setting. It affects the whole project and adds up to one physics tick of visual delay.
